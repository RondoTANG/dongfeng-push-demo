# 东风护卫军 AI 热点线索 PoC

本地可运行的 B 端产品原型，用于验证以下链路：

`公开信息采集 → 来源清洗 → 事件聚合 → 证据研判 → 原创增长草案 → 审批与实际发布 → 原创发布登记 → 后效快照 → 按需生成追加加热草案`

业务路径包括：

- **原创增长主链**：判断哪些事件值得组织原创评论或内容作业；实际发布后继续观察传播增长，由运营判断是否生成追加加热草案。
- **关联源内容直接加热支路**：当事件已有可执行的平台文章或视频时，可另行形成点赞、正向评论等互动草案。

原创发布后效是主链的组成部分，不是可有可无的附加分支。关联源内容直接加热与原创后追加加热同时保留，但两者的目标内容和触发条件不同。原型不创建正式作业、不触达用户，也不自动执行互动。

## 本地启动

```bash
python3 -m pip install -r requirements.txt
./scripts/start_local.command
```

浏览器打开：`http://127.0.0.1:8765/`

## 真实搜索配置

豆包搜索密钥只从环境变量或 macOS Keychain 读取，不写入仓库：

- 环境变量：`DOUBAO_SEARCH_API_KEY`
- Keychain 服务名：`guard-army-doubao-search`

未配置凭证时，页面和接口会返回真实失败状态，不使用 Mock 结果冒充采集成功。

Codex公开搜索使用本机Codex桌面应用的登录态，不要求另填API Key。默认从系统查找`codex`，也可通过`CODEX_CLI_PATH`指定本机可执行文件。

## 运行方式与自动采集

自动采集默认停止。管理员可在“运行中心”设置1—168小时的采集周期并开启或停止；首次开启或修改周期后等待一个完整周期，不会因启动服务立即产生搜索调用。启停、周期、下次执行时间和最近自动批次写入外置运行数据目录，重启后继续生效。

管理员也可确认后手工执行：

- 完整运行：任务数按“当前启用查询数×2个采集器”动态计算；默认17条查询、34个任务，3小时内不可重复启动。
- 快速验证：1条查询×豆包／Codex，共2个任务；10分钟内不可重复启动。

证据不足时，“发起补证”只生成补证方案；界面展示问题、搜索词、工具和预计调用次数，运营确认后才会执行Codex和／或豆包定向搜索。

## 访问控制与手机端

- 本地首次启动会在 `data/admin_access.key` 生成管理员密钥；文件权限为仅当前用户可读，不纳入 Git。服务器部署时使用 `AI_HOTSPOT_ADMIN_KEY` 注入固定管理员密钥，并可设置 `AI_HOTSPOT_COOKIE_SECURE=true` 强制安全 Cookie。
- 管理员可在“访问密钥管理”生成、查看状态、再次查看／复制和撤销访客密钥。登录校验仍使用加盐哈希；完整密钥以服务器主密钥加密保存，重新查看时必须再次输入管理员密钥，并记录审计。
- 访客登录后只能查看数据，不能看到访问密钥管理菜单，也不能通过接口执行采集、审核、配置或其他写操作；权限同时由前端和服务端约束。
- 页面已适配桌面、平板和手机。手机端使用抽屉式导航；事件审核、作业草案和原创后效均采用“列表 → 独立详情 → 返回列表”，列表和详情不再同屏，也不使用嵌套滚动区。当前对象的审核、编辑、补证、录入快照等操作固定在底部安全区；筛选、查询、翻页等浏览操作仍留在内容区。草案详情按标题、章节、条目和正文建立阅读层级，编辑／审批抽屉使用单列布局并可完整滚动。

部署到服务器时应设置固定的 `AI_HOTSPOT_KEY_ENCRYPTION_SECRET`，用于加密可再次查看的访客密钥；本地未设置时会在 `data/access_key_encryption.key` 自动生成仅当前机器使用的主密钥。该主密钥和管理员密钥均不得提交到 Git。

## 数据与边界

- SQLite 运行库位于 `data/ai_hotspot_poc.db`，已被 `.gitignore` 排除。
- 公开搜索只用于发现线索，不能单独证明真实热点。
- 同一URL只保留一条来源数据，但每个搜索工具、查询词和搜索获取时间分别留痕。
- 工作台独立显示来源平台、搜索来源（豆包／Codex，可同时出现）、正文或搜索摘要、发布时间和搜索获取时间。摘要不冒充完整原文，详情保留发布时间依据和逐条发现记录。
- 以采集时刻前72小时为有效发布时间窗口，优先近24小时。正文头部的发布元信息优先于供应商日期；不把正文叙事日期、网页索引时间或搜索时间当成发布时间。超过窗口记为旧闻；无法核验或未来日期暂不纳入有效线索，均可在无效记录追溯。旧事件的新回应必须有独立近期内容证据。
- 风险标签统一由`../config/清洗聚合与判定规则_v0.1.yaml`的`risk_gate.rules`维护，配置管理的“风险标签”页展示中文名称、关键词与核验要求。修改文件后点击“重新读取配置”；关键词命中只提示核验，不等于负面定性。
- 品牌、查询目录、来源平台和域名识别规则支持管理员在配置管理页面增删改。`../config/来源平台字典_v0.1.yaml`仍保存完整平台字典；页面将“采集器能力”（只读）与“平台定义／域名识别”（可编辑）分开，避免把技术能力误当业务配置。
- 旧的“人工研判／待补证／观察”事件状态启动时统一映射为待审核；补证进度单独记录，不与事件审核结论混用。
- 已停用历史样本导入接口与按钮，避免把历史搜索重导入当成新的采集。空产品标注不显示按钮；流程入口直接指向本地流程图，不使用外部占位说明。
- 新事件统一进入待审核；最终审核只有通过／驳回，事实结论和行动方向仅在通过时选择。
- 原创增长草案生成完整作业要求，包括作业详情、话题、核心命题、证据、分平台指引、创作方向和规则边界。
- 源内容加热草案必须绑定当前事件中的可执行平台来源、URL和至少一项互动动作。
- 原创后二次加热草案必须绑定实际发布记录和触发判断；至少两个同一内容、同口径快照后才允许生成。
- 正式系统可后续选择标准数据推送或受控 MCP 调用；MCP 不是本地 PoC 的前置依赖。
