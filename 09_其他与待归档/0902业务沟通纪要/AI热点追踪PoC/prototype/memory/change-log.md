# 项目变更记录

## 2026-09-05

- 业务主链修正：根据会议纪要与用户确认，将“原创增长→实际发布→后效快照→增长判断→按需追加加热”恢复为主业务闭环；“事件有可执行关联文章／视频时是否直接加热”作为补充支路。三类 `draft_purpose` 和现有数据结构保留，本次统一修正PRD、HTML、供应商数据要求、原型页面和服务说明的逻辑优先级。
- 执行能力补齐：基础查询改为豆包＋Codex双路执行，新增多路发现追溯、旧闻自动无效、搜索／发布时间筛选、定向补证预览与确认、事件通过／驳回联动、完整作业要求初稿和全列表服务端分页。
- 付费调用保护：自动每3小时采集改为默认暂停，启动服务不产生搜索调用；完整及快速运行分别实施3小时和10分钟服务端冷却。

- 创建项目基础框架。
- `step-01`：建立 FastAPI＋SQLite 本地服务底座、完整业务对象表结构、健康检查、静态托管和一键启动脚本；运行时数据库已加入忽略规则。
- `step-02`：接入现有豆包 Global Search 调用器与 Keychain 配置，新增真实样本导入、快速／完整查询、配置快照、来源标准化、URL 归一、平台识别、自动无效过滤及运行／来源／无效 API。
- `step-03`：新增确定性事件初聚合、官网列表页拆分、品牌／动态实体识别、风险标记、热点不可判定原因、证据绑定、Codex 工作项领取与结构化回传，以及事件人工合并／拆分接口。
- `step-04`：新增事件人工审核、草案生成条件、原创评论／原创内容草案、平台与现有能力标签建议、证据和禁用表述、草案编辑与审批状态机；流程终点固定为 approved／rejected，不创建发布与效果对象。
- `step-05`：按成长体系后台的布局规律重建统一应用壳、6 页导航、面包屑、服务状态、设计 token、表格／状态／表单／抽屉组件和错误态；采用克制的工业运营台风格，保留三视图内部切换。
- `step-06`：运行中心与线索工作台接入真实 API，新增实际批次／覆盖／来源指标、快速与完整运行、真实样本导入、运行详情、事件聚合入口、线索筛选、来源详情和事件下钻。
- `step-07`：新增事件队列与证据审核双栏、品牌关系、动态实体存疑、风险、热点数据准入原因、Codex 工作项状态、事件审核抽屉；新增草案列表、详情、证据下钻、编辑和人工审批，明确审批通过不等于正式下发。
- `step-08`：新增业务可读配置 API 和页面，展示9品牌、17查询、来源／域名、自动无效、去重聚合、草案范围与热点数据准入；配置版本可追溯到历史批次，无效日志与业务操作审计分栏展示。
- `step-09`：采集脚本扩展为“采集→来源处理→事件聚合”可重入执行器，新增 Codex 工作项领取／回传 CLI 和契约校验；已创建每3小时本地 Codex 自动化，不依赖 MCP，运行中心展示自动化与工作项状态。
- `step-10`：补齐业务可读功能说明、本地处理与服务流程图、异常与边界口径；完成真实运行→来源→事件→审核→草案→审计的数据追溯，并为6个核心页面补齐稳定标注锚点。
- 方向修订：按用户确认把业务问题拆为两条并列路径——“哪些热点值得发原创作业”和“如何对热点本身的文章／视频生成点赞、正向评论等加热作业”。新增 `draft_purpose`、目标来源／URL／内容标题和互动动作字段；同一事件可生成原创增长与源内容加热两类草案并分别审批。源内容加热不等待原创投稿，本期仍不进入正式下发、任务执行和发布后效果追踪。
- 后效闭环修订：保留上述两类初始路径，同时补入原创增长的发布后分支。新增原创发布登记、指标快照、同口径增量、运营后效判断和 `original_post_boost` 草案；热点源内容加热绑定 `target_source_id`，原创后二次加热绑定 `target_submission_id`，分别触发与审批。仍不创建正式作业、不自动执行互动。
