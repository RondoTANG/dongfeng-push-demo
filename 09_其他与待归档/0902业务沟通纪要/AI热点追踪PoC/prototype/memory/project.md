# 项目记忆

## 项目定位

- 项目名称：东风护卫军 AI 热点线索与作业草案联动 PoC
- 当前迭代：AI热点线索PoC：双路作业草案生成与审批。
- 迭代说明：本地可运行原型，流程截止到原创增长与源内容加热两类草案分别人工审批。
- 创建日期：2026-09-04
- 产品形态：护卫军 B 端运营后台＋本地 FastAPI 服务＋SQLite 持久化。
- 参考底座：`04_成长与激励体系/04_成长体系UI原型` 的后台布局与视觉规范，仅参考、不修改原项目。

## 产品目标

验证公开搜索线索能否经过统一清洗、事件聚合、证据研判和人工审核，稳定形成两类可追溯草案：一类围绕值得响应的事件组织原创内容增长，另一类直接对事件中的具体平台文章或视频组织点赞、正向评论等加热。业务终局希望识别真实热点并自动组织响应；本期不承诺真实热点判定，也不替代专业舆情数据源。

## 当前能力与业务期望的差异

| 业务期望 | 本期可验证 | 本期明确不能证明 |
| --- | --- | --- |
| 发现哪个平台、哪个事件正在快速发酵 | 从豆包公开搜索和 Codex 可访问网页中发现东风相关公开线索，识别来源平台并聚合事件 | 未知链接前的全平台完整覆盖、平台原生互动量和连续增速 |
| 判断是否是真实热点并及时响应 | 给出证据、缺失项、风险提示和“是否值得形成作业草案”的运营建议 | 仅凭搜索结果数量或 AI 主观评分判定真实热点 |
| 判断哪些热点值得发原创作业 | 运营基于公开线索、证据、风险和品牌关系选择“原创增长”，系统生成原创评论／内容草案并单独审批 | 系统自动证明真实热点、正式作业下发和任务执行 |
| 判断如何加热热点源内容 | 运营从事件证据中选择具体平台文章或视频，系统生成绑定目标URL和互动动作的源内容加热草案并单独审批 | 自动证明目标内容真实热、自动集中点赞／评论、原创投稿后的效果追踪与二次加热 |

## 目标用户

- 运营审核人员：处理事件候选、核验证据、修改并审批作业草案。
- 产品管理员：维护品牌、查询、来源、清洗、聚合和任务规则。
- 数据／规则管理员：检查运行覆盖、失败原因、配置版本和审计记录。
- 研发或 IS 观察者：评估接口、稳定性、数据边界和后续企业化改造条件。

## 核心页面列表

1. 运行中心：查看三小时周期、手动运行、查询覆盖、分步数量、耗时和失败重试。
2. 信息线索工作台：按来源平台、品牌关系、有效状态和时间筛选线索。
3. 事件详情：查看聚合来源、证据时间线、品牌关系、存疑原因并完成人工结论。
4. 双路作业草案与审批：分别查看原创增长草案和源内容加热草案；后者展示目标内容、平台、URL和互动动作；两类草案均支持编辑、通过和驳回。
5. 配置管理：可读化展示并维护品牌、查询、来源、清洗聚合、草案生成和热点数据准入规则。
6. 无效与审计记录：分开记录自动无效、人工否决、配置变更和关键操作。

## 核心用户路径

运行批次创建 → 豆包公开搜索采集 → 来源标准化与自动无效过滤 → 事件聚合 → Codex 补证／语义研判 → 运营审核事件 → 选择原创增长、源内容加热或两者同时 → 生成对应草案 → 两类草案分别修改和审批 → 审计留痕。

流程在“草案审批结果已记录”处结束，不向正式护卫军系统推送。

## 主要数据对象

- `collection_run`：一次完整运行批次及覆盖、配置快照和提供方结果。
- `query_job`：运行批次中的单条查询任务及重试状态。
- `raw_provider_result`：提供方原始响应索引，原文不在前端泄露凭证。
- `source_item`：统一后的公开来源内容。
- `invalid_log`：自动无效结果及规则原因。
- `event`／`event_evidence`：统一事件、聚合来源与证据。
- `candidate_review`：事件候选的运营审核结论。
- `task_draft`：带 `draft_purpose` 的原创增长或源内容加热草案；记录证据、目标来源／URL、互动动作、风险和审批状态。
- `audit_log`：配置和业务操作审计。

## 交付方式

- 本机一条命令启动 FastAPI、SQLite 和静态后台。
- 核心页面只读取真实 API；没有凭证、没有数据或接口失败时展示真实状态，不用前端 Mock 冒充成功。
- 首轮导入或执行真实豆包结果，验证从运行到两类草案分别审批的完整追溯。
- 验证通过后，再创建每三小时唤醒一次的 Codex 自动化；自动化负责调度和补证，业务状态由本地服务持久化。

## 已确认假设

- 当前为本机单用户 PoC，不实现登录、组织和细粒度权限后台。
- 豆包 Global Search 是首个真实采集适配器；Codex 是补充公开证据和生成结构化分析的执行者，不是企业级数据源。
- 搜索来源的 `hotspot_status` 固定为 `unknown`，同时记录不可判定原因。
- 9 个品牌及别名为当前品牌主数据；车型、人物、活动在事件内动态识别，存疑时写原因交人工判断。
- 状态流转、去重、无效过滤、配置快照和审批由确定性程序执行；生成式 AI 不负责字符级 JSON 透传或确定性状态写入。

## 工作原则

- 当前 PRD、配置 YAML、实际接口返回和用户已确认范围优先于历史方案。
- 公开搜索只作为线索来源，页面不得将其包装成“热点监测已完成”。
- 业务可读配置与 YAML 同步呈现；运行批次必须冻结实际生效版本。
- 凭证只从环境变量或 macOS Keychain 读取，不入库、不入前端、不入 Git。
