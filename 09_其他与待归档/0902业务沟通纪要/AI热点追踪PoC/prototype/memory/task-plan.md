# 任务计划

## 迭代目标

交付一套本地可运行的东风护卫军 AI 热点线索 PoC：以真实豆包公开搜索结果为输入，完成运行追踪、来源处理、事件聚合、Codex 补证／研判，以及“原创增长”“热点源内容加热”两类作业草案生成和分别人工审批。流程在草案审批留痕处结束。

## 需求单元与依赖

| 步骤 | 需求单元 | 用户可观察结果 | 主要依赖 |
| --- | --- | --- | --- |
| STEP-01 | 本地服务与数据底座 | 一条命令启动，健康检查成功，SQLite 可持久化 | None |
| STEP-02 | 真实采集与来源处理 | 可导入真实样本或发起豆包查询，生成运行、查询、来源、无效记录 | STEP-01 |
| STEP-03 | 事件聚合与工作项 | 有效来源聚合为事件，热点显示不可判定及原因，Codex 工作项可领取和回传 | STEP-02 |
| STEP-04 | 事件审核与双路草案生成 | 运营审核事件后可生成原创增长、源内容加热或两类草案，源内容加热绑定具体文章／视频 | STEP-03 |
| STEP-05 | 后台应用壳与设计系统 | 统一侧栏、顶栏、路由、API 错误态和成长体系后台风格 | STEP-01 |
| STEP-06 | 运行中心与线索工作台 | 页面可发起运行、看进度、筛选真实线索和无效原因 | STEP-02、STEP-05 |
| STEP-07 | 事件详情与草案审批 | 页面可核验证据、查看存疑原因、审核事件和修改审批草案 | STEP-04、STEP-05 |
| STEP-08 | 配置管理与审计 | YAML 规则转为业务可读配置，运行与审批可追溯 | STEP-02、STEP-05 |
| STEP-09 | 本地运行器与三小时自动化准备 | 可重复执行完整／快速运行，Codex 工作项接口有机器可调用说明 | STEP-03、STEP-08 |
| STEP-10 | 异常态、说明文档与全链路联调 | 无凭证、断网、空数据、部分失败均不伪造成功；6 页和完整流程可验证 | STEP-06、STEP-07、STEP-08、STEP-09 |

## 页面交付范围

- 运行中心：批次、覆盖、提供方、查询任务、手动执行和失败重试。
- 信息线索工作台：有效／待判定线索，平台、站点／账号、品牌和时间筛选。
- 事件详情：来源证据、品牌关系、实体存疑、风险、热点不可判定原因和事件审核。
- 双路作业草案与审批：原创增长草案；绑定具体平台文章／视频、URL和互动动作的源内容加热草案；两类草案分别编辑、通过或驳回。
- 配置管理：品牌、查询、来源、处理、草案和热点数据准入规则的业务可读视图。
- 无效与审计记录：自动无效与人工／系统操作分栏查询。

## 服务交付范围

- FastAPI＋SQLite 本地服务。
- 豆包 Global Search 适配器和真实样本导入器。
- 确定性来源处理、无效过滤和事件初聚合。
- Codex 工作项领取与结构化回传。
- 事件审核、双路作业草案生成、目标来源校验与草案分别审批。
- 配置快照、业务配置读取和全链路审计。

## 交付边界

- 不接正式护卫军作业发布接口。
- 不做 MCP、正式作业下发、任务执行、原创投稿回流、发布后效果追踪和二次加热页面。
- 不把公开搜索结果数当热度；本期热点状态固定 `unknown`，并展示具体原因。
- 不以 Mock 数据冒充运行结果；允许导入已有真实豆包样本用于第一次可重复验证。

## 验证策略

- 每个 STEP 实现后调用 `prototype-verifier`；涉及页面、DOM、交互、截图和响应式时使用 `playwright-cli`。
- 服务步骤执行真实 API／SQLite 验证；界面步骤同时核对 API 返回和页面展示。
- 全局完成前使用 `verification-before-completion`，失败时使用 `systematic-debugging`。
