# 东风护卫军热点数据采集与交付要求

## 1. 评估目的

本次评估供应商是否具备以下生产级数据能力：

1. 在业务未提供具体链接时，从目标平台主动发现新增内容。
2. 对指定账号的新增内容进行保底采集。
3. 对已知文章或视频持续采集平台原生互动指标，保留历史快照。
4. 稳定交付可追溯、可复算、可审计的原始数据。

采集不得按内容倾向过滤，正面、中性和负面内容均需按同一采集范围返回。

供应商只负责内容发现、原始数据采集、指标更新和数据交付。东风护卫军系统自行完成事件聚合、热点计算、倾向与风险研判、原创作业决策和加热作业决策。

## 2. 目标平台

请按平台分别说明实际支持能力：

- 抖音、快手、微博、微信视频号。
- 今日头条、微信公众号、小红书、知乎、B站。
- 易车、懂车帝、汽车之家。

不接受“全网覆盖”或“主流平台均支持”等概括答复。

## 3. 需要评估的三类采集场景

### 3.1 未知链接前的主动发现

业务只提供品牌、行业主题、重点账号或关注范围，供应商需主动发现相关平台的新增内容。

每个平台需说明：

- 发现入口：平台原生搜索、话题页、热榜、推荐流、账号动态、评论区、授权接口或其他合规入口。
- 召回范围：支持的内容类型、账号类型、公开范围和历史时间范围。
- 更新机制：常规扫描频率、最短扫描间隔、增量识别和失败补采。
- 发现时延：从平台发布到首次交付的典型时延和承诺时延。
- 覆盖边界：登录态、私域、地域、限流、删除或平台风控等已知盲区。

搜索引擎结果只能作为补充发现来源，必须与平台原始内容分开标记。搜索排名和结果数不能作为平台热度指标。

### 3.2 指定账号持续监测

针对品牌官方账号、重点媒体、行业账号、KOL或业务指定账号，采集：

- 新增内容及其平台内容ID、原始链接和发布时间。
- 账号稳定ID、名称、主页、认证类型和粉丝数等可得字段。
- 内容的播放／阅读、点赞、评论、转发／分享、收藏等平台原生指标。

请说明账号配置方式、数量上限、更新频率、授权条件和账号失效处理方式。

### 3.3 已知内容持续追踪

业务会提供两类已知链接：

1. **护卫军原创发布链接**：用于判断原创发布后是否出现传播增长，是否需要追加加热作业。
2. **热点事件关联文章或视频链接**：用于持续观察该源内容的传播变化，支撑是否直接加热的业务判断。

对两类链接均需：

- 按平台原始口径采集播放／阅读、点赞、评论、转发／分享、收藏等可得指标。
- 保留每次实际采集时间和累计值，不得只覆盖为最新值。
- 记录正常、删除、隐藏、限流或不可访问等内容状态。
- 允许指定内容提高更新频率或延长跟踪周期。

## 4. 必须交付的数据

### 4.1 内容字段

- 平台、平台内容ID、内容类型。
- 原始链接、标题、正文或可获取的原文片段、话题标签。
- 发布时间、供应商首次发现时间、本次采集时间。
- 内容状态、数据来源类型、采集状态、缺失字段及原因。
- 平台能提供时，增加原发、转载、引用、回复或关联话题关系。

正文或指标无法获取时必须返回空值和缺失原因，不得用`0`、AI生成内容或估算值代替。

### 4.2 作者或账号字段

- 平台作者ID、作者名称、主页链接。
- 认证类型、粉丝数、账号原始分类和采集时间。
- 无法确认时返回未知和原因，不得仅根据昵称推断官方、媒体或KOL身份。

### 4.3 互动指标与快照

- 平台可得的播放／阅读、曝光、点赞、评论、转发／分享、收藏等原生指标。
- 快照时间、实际采集时间、采集状态和缺失原因。
- 最低评估快照点：首次发现、首次发现后1小时、3小时和24小时。

不同平台指标必须保留各自原始口径，不得未经说明换算为统一热度值。

### 4.4 评论与传播关系（如支持）

请明确说明是否支持，以及采集范围、排序方式和最大采集量：

- 评论ID、所属内容ID、评论正文、作者ID、发布时间、点赞数、父评论ID。
- 原发、转载、引用、回复、父子评论、话题或榜单关系。

## 5. 交付方式与基本规则

优先通过HTTP API、Webhook或消息推送交付JSON数据，并支持：

- 按时间和平台增量获取。
- 按内容ID或指定账号查询。
- 历史数据补拉和指定内容重新采集。
- 分页／游标、幂等、失败重试、错误码、限流说明和版本管理。

数据必须能追溯至平台、内容ID、作者、原始链接、采集时间和数据来源。不同采集方式（官方接口、账号授权、平台公开页、搜索引擎等）必须明确区分。

## 6. 供应商答复表

请每个平台单独填写：

| 评估项 | 供应商需说明 |

| 未知链接主动发现 | 是否支持；具体发现入口和覆盖范围 |
| 指定账号监测 | 账号类型、数量上限、授权条件和更新频率 |
| 已知内容追踪 | 支持的链接类型、最短快照间隔、跟踪周期和补采方式 |
| 内容类型 | 图文、文章、帖子、笔记、视频、动态、评论的支持情况 |
| 内容倾向覆盖 | 是否不过滤正面、中性和负面内容 |
| 发现频率与时延 | 常规频率、最短间隔、典型时延和承诺时延 |
| 平台内容ID和作者ID | 是否提供稳定原生ID |
| 原生指标 | 可提供的播放、阅读、点赞、评论、转发、收藏等字段 |
| 评论与内容关系 | 采集范围、最大数量、父子／转载／引用关系支持情况 |

同时提供字段字典、状态码、脱敏样例JSON、接口文档、覆盖限制和PoC实施计划。

## 7. PoC验证项

1. **未知内容发现**：不提供具体URL，只提供关注范围；对照业务已知样本，记录发现入口、发现时延和漏采原因。
2. **指定账号完整性**：对照账号实际发布记录，验证新增内容召回和时延。
3. **已知内容连续快照**：同时选择原创发布链接和热点关联源内容链接，验证首次、1小时、3小时和24小时快照。
4. **字段和追溯**：验证内容ID、作者ID、原始链接、时间、原生指标、缺失原因和采集来源。
5. **异常处理**：验证删除、隐藏、限流、重复数据、失败重试和历史补拉。

PoC验收的是数据发现和交付能力，不验收供应商的主观热点分、情感结论或业务处置建议。具体SLA阈值在能力答复和真实样本回放后确认。

## 8. 请供应商重点回答

1. 在不知道具体文章或视频链接时，如何从各目标平台主动发现新增内容，发现时延和漏采边界是什么？
2. 对已知内容（包括护卫军原创内容和热点关联源内容），能否持续提供平台原生互动指标和历史快照？
3. 每个平台实际可提供哪些内容ID、作者ID、原生指标、评论和传播关系字段，交付频率、时延、稳定性和合规条件如何？
