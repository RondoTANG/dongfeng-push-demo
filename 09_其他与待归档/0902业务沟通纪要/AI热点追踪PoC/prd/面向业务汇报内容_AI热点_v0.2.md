# 面向业务汇报内容：AI热点能力（v0.2）

> 用于替换原PPT中把“联网搜索”直接表述为“热点发现”的内容。本稿只写汇报结论和方案，不写产研思考过程。

## P1 业务期望：用正在发酵的事件驱动原创作业

**页标题：从“运营找题”升级为“热点触发原创作业”**

业务目标不是多搜几篇新闻，而是识别：**哪个平台、哪个事件正在快速产生讨论，以及护卫军是否需要响应。**

完整业务闭环：

1. 持续监测微博、抖音等目标平台。
2. 识别正在增长的事件及所在平台。
3. 判断与东风、子品牌、车型和品牌人物的关系及风险。
4. 自动生成原创作业草案。
5. 按成员擅长平台标签分发。
6. 24小时内完成原创发布。
7. 监测投稿内容的传播增长。
8. 对起量内容触发全员点赞、正向评论等加热作业。

页底结论：**“热不热”决定是否响应，“在哪里热”决定发给谁，“发布后是否起量”决定是否继续加热。**

## P2 当前能力：可以找到公开线索，但不能证明真实热点

**页标题：当前搜索能力支持“找线索”，暂不支持“判热点”**

| 当前工具 | 当前能做 | 当前不能证明 |
|---|---|---|
| 豆包Global Search | 返回公开网页标题、摘要、URL、站点和部分时间 | 平台原生播放、互动、UGC规模及增长速度 |
| Codex公开搜索 | 补充检索、打开页面、核验证据、整理事件 | 目标平台完整覆盖、分钟级增量、生产SLA |
| AI分析 | 摘要、聚类、东风关联、风险提示、任务草案 | 不能用主观评分替代平台真实热度 |
| 项目现有数据采集 | 用户回填原创链接后，除公众号、视频号外，可按平台采集点赞、评论等基础指标 | 不能在未知链接前发现全平台热点；不同平台可采指标不一致 |

实测结论：

- 3类“热点”查询取得9条搜索结果，均有网页来源依据。
- 返回字段没有播放、点赞、评论、转发、作者权重和时序增速。
- “岚图汽车 热点”仍返回6月、8月内容。

页底结论：**搜索结果有网页依据，但没有热点依据；被搜到不等于正在发酵。**

## P3 需求判断：业务目标明确，但现有能力只能覆盖部分链路

**页标题：对照业务期望，当前核心差距不在AI分析，而在热点数据来源**

| 业务期望 | 当前能力 | 判断结论 |
|---|---|---|
| 判断哪个平台、哪个事件正在快速发酵 | 豆包＋Codex只能检索已被公开收录的网页内容 | **当前不可判定真实热点**；缺少平台原生互动量、连续时序增速、独立作者/UGC数量和完整平台覆盖 |
| 判断事件是否与东风相关、是否值得响应 | 可基于来源证据进行事件聚合、东风关联和风险提示 | **可以验证**，但高风险内容仍需运营审核 |
| 热点出现后自动生成原创作业 | 可根据已核验事实生成原创评论或原创内容作业草案 | **可以验证草案质量**，当前不自动发布 |
| 按成员擅长的平台下发 | 已有平台能力标签，可设计匹配规则 | **可以验证匹配逻辑**，真实下发需接标签和作业接口 |
| 监测投稿起量并触发加热作业 | 用户完成原创后回填链接；项目现有采集能力可获取非微信平台的点赞、评论等基础指标，系统可按时间保存多次快照并计算增量 | **可以验证并落地非微信平台的加热触发**；公众号、视频号暂由截图/人工确认，具体阈值按平台配置 |

判断总结：

1. 业务提出的“热点驱动作业”需求已理解，完整目标成立。
2. 现有搜索和AI能力可以覆盖“找公开线索—理解事件—生成任务草案”；现有数据采集可在用户回填原创链接后，覆盖非微信平台的基础效果监测和加热触发。
3. 当前真正缺失的是最前端的真实热点发现，以及公众号、视频号的自动效果采集。因此方案应分段建设：先验证现有能力可完成的线索处理、任务草案和非微信平台加热链路，再引入稳定数据源验证真实热点。
4. **本阶段PoC达标，只代表线索处理和任务草案链路可行，不代表已经具备热点监测能力。**

## P4 本阶段PoC方案：公开信息线索与作业联动PoC

**页标题：基于上述判断，先用10天验证“线索—原创—效果—加热”分段闭环**

PoC目的不是证明系统已经能够找到热点，而是验证在热点数据源尚未具备时，来源核验、事件理解、东风关联、风险判断、原创作业生成，以及用户回填链接后的效果监测和加热触发是否可行。

```text
9个品牌查询＋8个行业查询
            ↓
豆包与Codex公开搜索
            ↓
来源核验、旧闻/促销/同名噪声过滤
            ↓
事件去重聚合、东风关联、风险门禁
            ↓
相关事件线索 / 品牌内容机会
            ↓
生成原创评论或原创内容作业草案
            ↓
运营审批（不自动发布）
            ↓
用户完成原创并回填平台链接
            ↓
非微信平台采集初始值及后续快照
            ↓
按平台计算点赞/评论等指标增量
            ↓
达到平台阈值后生成加热作业草案
```

本阶段所有搜索线索统一标记：

```text
热点判定能力：不具备
热点状态：未知
不可判定原因：当前数据仅为公开搜索结果，缺少平台原生互动量、连续时序增速、独立作者/UGC数量及完整平台覆盖，无法证明事件正在发酵
事件类型：相关事件线索 / 品牌内容机会
```

运行方式：本阶段每日人工触发一次完整运行，不建设生产定时任务。

产出数据：查询覆盖、来源证据、无效日志、待确认实体、统一事件、候选决策、原创任务草案、用户回填链接、效果指标快照、增量结果和加热任务草案。

## P5 SMART：本阶段承诺什么

**页标题：PoC验收针对“线索与任务链路”，不针对真实热点准确率**

| 维度 | 本阶段承诺 |
|---|---|
| S 具体 | 完成公开线索搜索、证据核验、清洗聚合、品牌关联、风险提示、原创作业草案，以及非微信平台“回填链接—指标快照—增量判断—加热草案” |
| M 可衡量 | 每次17条基础查询×2个搜索来源；来源字段完整率100%；所有搜索事件热点状态保持未知；记录候选通过率、线索漏检率、回填链接解析成功率、指标采集成功率、增量计算完整率和加热判断人工认可率 |
| A 可实现 | 复用当前豆包、Codex、本地规则、运营审核及项目已有数据采集能力；公众号、视频号采用人工凭证兜底 |
| R 相关 | 同时验证热点运营闭环的任务生成和后置加热能力，并用真实样本明确只剩前置热点发现及微信系采集缺口 |
| T 有时限 | 第0天冻结配置；第1—7天人工运行；第8—9天复盘；第10天形成PoC结论和下一阶段建议 |

明确不承诺：全平台热点覆盖、真实热点评级、爆发预警、无需审批的自动下发。非微信平台可以生成加热作业草案；是否自动发布仍保留运营门禁。

## P6 下一阶段：验证真实热点所需的数据底座

**页标题：复用现有采集完成后置加热，新增数据源补齐前置热点发现**

现有能力可直接复用：

- 用户完成原创后回填平台链接。
- 抖音可采点赞、评论；快手可采点赞、评论、转发；微博可采转发、评论、点赞。
- 今日头条、小红书、知乎、B站、易车、懂车帝、汽车之家可采各自部分播放/阅读或互动指标。
- 系统对同一链接保存多次快照并计算增量，达到分平台阈值后生成加热作业草案。
- 公众号、视频号暂不支持自动采集，通过结果截图或人工确认兜底。

仍需新增的数据能力，是在用户尚未提供链接前持续发现全平台事件并判断是否正在发酵。

候选数据源必须提供：

- 平台、账号、平台内容ID和原始发布时间。
- 播放/曝光、点赞、评论、分享、收藏等原生指标。
- 至少可计算1小时、3小时、24小时增量的连续快照。
- 独立作者数、UGC新增量及账号影响力字段。
- 平台覆盖、采集延迟、漏采说明、失败重试和审计留痕。

验证方式：先选一个业务优先平台和一组已知事件回放，比较系统曲线与运营人工判断；通过后再分平台标定热点阈值。

需业务确认：

1. 首个真实热点PoC优先平台。
2. 可采购或授权的数据源范围。
3. 热点后优先生成的作业类型及24小时响应要求。
4. 平台标签、作业下发和效果回流接口的接入顺序。

页底结论：**专业数据解决“真不真、热不热、稳不稳”；AI解决“事件怎么理解、是否与东风相关、作业怎么生成”。**
