# 护卫军体系交互设计与原型规范 (Rules)

> 项目业务全景、当前优先级、模块状态与风险统一参考：`.agents/PROJECT_UNDERSTANDING.md`。
> 开始修改前还需阅读根目录 `AGENTS.md` 与 `docs/project-memory/CURRENT.md`；若与真实代码或最新会议冲突，以后者核实后的事实为准。

## 一. 原型设计与展示习惯
* **多场景平铺对比布局**：在同一个 HTML Demo 页面内，针对同一个业务模块，如果存在多种状态（如：有可做作业、无可做作业、筛选开启状态等），**必须采用同屏平铺多设备的布局（如 flex gap 排列横向多部手机）** 进行穷举展示。不要仅仅通过文字描述或只写在被注释掉的代码里，要让研发和测试一眼看出状态的区别。

## 二. 统一的右侧批注区规范
* 页面结构必须包含右侧独立的固定宽度的批注区（如 `w-[350px] shrink-0`）。
* 批注区必须使用统一的样式：包含 `.annotation-block` 容器、`.annotation-title` 标题和 `.annotation-text` 正文内容（引用自 `common.css` 中的红底标样式）。
* 每个涉及动态判断（CTA 按钮状态切换、条件标签显隐等）的地方，必须在批注区专门写一个 `【逻辑说明】` 批注块，清楚地写明「判断条件」、「不同场景下的文案与 UI 颜色差异」及「兜底逻辑」。

## 三. 后台统一导航结构与 UI 规范
* **全局菜单一致性**：在生成、重构或修改任何 B 端（运营管理后台）或 C 端 HTML 原型时，必须保证导航菜单与以下【护卫军全局菜单架构树】保持**绝对一致**。
* **护卫军平台全端系统菜单架构树 (强制遵守)**：
  * **B端 (运营管理后台)**:
    - 📝 作业管理：作业管理
    - ✅ 审核管理：审核管理列表 / 人工审核 / 反馈审核列表 / 作业审核记录
    - 👥 用户管理：平台列表 / 用户列表 / 员工列表 / IAM员工列表 / 用户标签管理 / 人群包管理
    - 📄 内容管理：文章编辑 / 广告管理 / 作业、千人千面、品牌素材管理 / 素材库 / 学院相关管理 / 优质内容管理
    - ⚙️ 系统设置：系统日志 / 登录日志 / 公众号管理 / 成长规则配置 / 额外奖励设置 / 积分充值管理 / 积分发放记录 / 标签管理(统计) / 字典管理 / 消息推送 / 白名单作业管理 / 作业用途分类管理 / 文章管理 / 审核话术管理 / 服务号消息额度管理
    - 📊 统计分析：成长数据大盘 / 用户、护卫军作业台账 / 党委排名数据 / 用户排名数据 / 累计零积分党委人数 / 累计零积分用户明细
    - 🤖 智能体：全局悬浮生态巡航分析智能体
  * **C端 (用户前台触点)**:
    - 🏠 首页 / 护卫军功能导航
    - 🎯 作业大厅：可接任务列表 / 任务详情与提交凭证
    - ⭐ 成长中心：成长体系主视觉大盘 / 成长值(XP)历史明细流 / 体系规则与权益介绍
    - 👤 个人中心：个人资产与设置
* **禁止随意删减**：无论本次需求是否只涉及局部模块（如“公众号管理”或“XP 配置”），B 端侧边栏必须展示上述**完整的系统级菜单结构**。如果是原生 HTML 方案，请直接复用 `04_成长与激励体系/04_成长体系UI原型/b_sidebar.js` 的实现。绝对不允许为了省事而生成只有局部节点的残缺菜单。

## 四. 业务术语与沟通规范
* **禁用“高薪/薪酬”等货币化词汇**：护卫军体系的激励物是“积分（Points）”与“成长值（XP）”，两者已彻底解耦。在沟通、编写 PRD 或设计 UI 文案时，**绝对禁止使用“高薪任务”、“赚佣金”、“发工资”等带有现金色彩的词汇**，必须严格统一为“高积分任务”、“高优作业”、“赚积分/攒XP”。
* **双轨制解耦概念**：时刻牢记“积分”对应的是外部大盘奖励（商城兑换），而“XP（成长值）”对应的是内部体系的段位升降（权限控制）。两者独立结算，互不干涉。

## 五. 公众号推送感知与技术路径规范
* **开放平台服务商授权**：严禁向任何子品牌索要 AppID/Secret。必须通过微信第三方开放平台扫码托管，获取并持久化 `authorizer_refresh_token`。
* **Webhook 5秒响应与去重**：接收到 `MASSSENDJOBFINISH`（群发完成）推送后，必须在 5 秒内返回 `"success"`。必须使用 `ArticleUrl` 或 `MsgID` 进行分布式锁与排他唯一去重。
* **免依赖网页元数据提取**：抓取 `ArticleUrl` 时，通过轻量 HTTP GET 解析 `og:title`、`og:image`、`og:description` 及 JS 变量 `ct`（发布时间戳），自动创建 `pending_review` 初始作业。

## 六. AI 审核与人机协同规范
* **人机协同双审机制**：AI 审核仅作前置风控与自动打标/初审，高风险或争议作业必须自动打入人工复审核流（支持审核话术库与快速判决）。
* **证据链存证**：AI 审核判定结果需记录匹配度得分、敏感词触发位置及匹配规则 ID，供 B 端【作业审核记录】与【反馈审核列表】查验。

## 七. 用户标签与党委组织树规范
* **组织结构与人群包**：用户管理必须兼容集团/党委/支部三级组织结构，支持基于标签（动态/轮回覆盖）与党委归属划分人群包，实现作业与千人千面内容的精准投放。
